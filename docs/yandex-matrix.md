# Яндекс Distance Matrix в Routing Lab

Клиент: [src/yandex-matrix.js](../src/yandex-matrix.js).
HTTP-запрос выполняется в методе `YandexMatrixClient.request`:

```text
GET https://api.routing.yandex.net/v2/distancematrix
    ?origins=latitude,longitude|...
    &destinations=latitude,longitude|...
    &mode=driving
    &apikey=<ключ из серверного окружения>
```

Ключ не передаётся в браузер, результаты или сообщения об ошибках.

## Подключение

В UI: **Настройки → Источник дороги → Яндекс Matrix API / Локальный расчёт**.
Выбор сохраняется кнопкой параметров. Для обычного сценария затем запустите
расчёт; исторический тест пересчитывается при сохранении параметров.
`settings.matrixProvider` принимает `yandex` или `local`. У старых сценариев
значение `auto` сохраняет выбор по серверному окружению.

При `local` сервер не вызывает Яндекс, даже если ключ настроен. Используется
полная геометрическая матрица без пробок; настройка экономного режима сохраняется,
но применяется только при возврате к Яндексу. При явном `yandex` и отсутствии
подключённого клиента возвращается ошибка, без автоматической подмены геометрией.

В `.env` используется существующий `YANDEX_ROUTING_API_KEY`.
При наличии ключа сервер и `npm run test:orders` используют Яндекс автоматически.
Если ключа нет, сохраняется локальная геометрическая модель.

Необязательные параметры окружения:

```dotenv
# yandex требует ключ; local явно включает геометрическую модель
MATRIX_PROVIDER=yandex
# disabled — без пробок; enabled — пробки на момент запроса
YANDEX_MATRIX_TRAFFIC=enabled
```

По умолчанию включены пробки (`traffic=enabled`). Яндекс не позволяет
запрашивать прогноз пробок на прошедшее время. `enabled` означает дорожные условия
на момент HTTP-запроса, а не исторические пробки на выбранном срезе.

`enabled` — внутренняя настройка клиента: при ней параметр `traffic` в запрос
не передаётся, применяется режим Яндекса по умолчанию с пробками. Яндекс принимает
явное значение `traffic=disabled`, но отклоняет `traffic=enabled` как неверное enum.

Транспорт переводится в параметры API:

| Курьер | Яндекс |
| --- | --- |
| `DRIVING` | `driving` |
| `SCOOTER` (мотороллер/мопед) | `driving` |
| `BICYCLING` | `bicycle` |
| `WALKING` | `walking` |

Курьеры SCOOTER в этом проекте используют мотороллеры/мопеды на автомобильных
дорогах. Для них используется `driving` с пробками и ограничением скорости 40 км/ч:

```text
minutes_SCOOTER = max(minutes_Yandex, meters_Yandex / 1000 / 40 * 60)
```

Например, 4 км за 4 минуты превращаются в минимум 6 минут. Если Яндекс даёт
10 минут из-за пробок, сохраняются 10 минут. Это нижняя граница времени, а не
модель средней скорости: остановки и разгоны отдельно не моделируются.
Поправка применяется после чтения исходной ячейки; общий кеш хранит автомобильные
значения без поправки. DRIVING не изменяется. Дополнительных запросов нет.
Режим Яндекса `scooter` предназначен для электросамокатов и здесь не применяется.
DRIVING и SCOOTER используют одинаковые дорожные ячейки и общий кеш.
В режиме всегда свободных курьеров используется DRIVING.

## Как выполняется bulk

В настройках UI доступны два режима. `matrixMode=full` выбран по умолчанию и
загружает полную матрицу для сравнения. `matrixMode=economy` ограничивает варианты
по ближайшим соседям; `matrixNeighbors` задаёт начальное число соседей (1–20,
по умолчанию 5). Настройки сохраняются обычной кнопкой параметров. В историческом
режиме сохранение параметров запускает новый изолированный расчёт.

### Экономный режим

1. Для каждого заказа выбираются K ближайших других заказов по координатам
   (долгота масштабируется по широте). Направленные пары филиал ↔ заказ всегда входят.
2. Запрашиваются только выбранные пары, отсутствующие в свежем кеше. Повторяющиеся
   координаты объединяются. Незапрошенные пары получают `UNKNOWN`, а ответ Яндекса
   о недоступной дороге — `FAIL`; эти состояния различаются в диагностике.
3. Все пять алгоритмов работают с одним набором дорожных данных. Если хотя бы
   один алгоритм оставил заказ неназначенным, K удваивается; для таких заказов
   добавляются входящие и исходящие варианты соседства. Результаты пересчитываются.
   Расширение продолжается до назначения или рассмотрения всех соседей.
4. Выбирается объединение переходов итоговых маршрутов всех алгоритмов, включая
   возвращение в филиал. Переходы с возрастом более 10 секунд обновляются.
   Более свежие данные повторно не оплачиваются. Если времена изменились, все
   алгоритмы пересчитываются, а новые итоговые маршруты проверяются снова.
   После четырёх нестабильных проверок возвращается ошибка вместо неподтверждённого
   результата. Весь процесс завершается до выдачи результата пользователю.

Это проверка при расчёте, не реальная проверка в момент отправки: прототип пока
не моделирует dispatch. При отправке значительно позже расчёта требуется новая
проверка. Здесь используются пробки на момент запроса, а не на будущий выезд.

Начальное количество ячеек для N заказов с уникальными координатами составляет
не более `2N + N×min(K,N−1)` на дорожный режим. Для 100 заказов и K=5 — до 700
вместо 10 100. Расширения и обновления добавляют ячейки, поэтому 700 не является
лимитом полного запуска. Ограничения зоны/суммы/SLA могут заставить расширить
поиск даже тогда, когда назначение всё равно невозможно.

Экономный режим может упустить выгодный маршрут: соседство определяет геометрия,
а не реальные дороги. Exact в нём тоже ограничен выбранными переходами и не служит
эталоном полной матрицы. Для полного сравнения используйте `full`.

В `matrixStats` добавлены `calculationMode`, `expansionRounds`, `validationRounds`,
`selectedPairs`, `initialNeighbors`, `validated`, `validationFreshSeconds` и
`fullComparison`. HTTP-запросы и ячейки суммируются по всем этапам, включая повторы.

### Общий клиент и кеш

1. Берутся филиал и eligible заказы внутри зон.
2. Для исторического заказа используются исходные latitude/longitude; для ручного
   заказа координаты восстанавливаются из x/y карты.
3. Повторяющиеся координаты объединяются. Разные заказы остаются разными остановками,
   но используют одну дорожную точку; дорога между совпадающими точками равна нулю.
4. Для каждого участвующего вида транспорта строится отдельная направленная матрица.
5. Кешированные пары и переход точки в саму себя не запрашиваются.
6. Оставшиеся пары упаковываются в прямоугольники origins × destinations до 100 ячеек.
   Сравниваются жадная упаковка плотных прямоугольников и группировка одинаковых
   строк; выбирается вариант с меньшим числом HTTP-запросов.
7. Одновременно выполняется максимум 3 запроса. Матрица полностью готовится до
   запуска алгоритмов; пять алгоритмов не обращаются к API по отдельности.

Приоритет оптимизации — отсутствие повторных оплачиваемых ячеек: каждый отсутствующий
направленный переход запрашивается один раз для данного дорожного режима, кроме повторов
при временных ошибках. Это иногда требует больше HTTP-вызовов, чем квадратные блоки
10×10 с лишними диагональными ячейками. Например, для двух точек нужны 2 перехода;
клиент делает два GET по 1 ячейке вместо одного GET с 4 ячейками.
Абсолютный минимум HTTP-вызовов для любой разреженной матрицы не гарантируется.

Яндекс тарифицирует элементы матрицы, а не только HTTP-вызовы. Для N уникальных
точек без кеша нужно N×(N−1) ячеек на уникальный дорожный режим. DRIVING и SCOOTER повторно используют те же ячейки. Возвращение в филиал также включено
в матрицу, но отображается отдельно и не входит в SLA доставки.

## Кеш, ошибки и ответ

Кеш находится в памяти серверного процесса, TTL 1 минута при включённых пробках, 5 минут при `traffic=disabled`. Ключ кеша включает
направленные координаты, транспорт и traffic. Перезапуск очищает кеш. Одновременные
подготовки матриц выполняются последовательно, чтобы повторный запуск использовал
кеш первого. Завершённые пакеты сохраняются даже при ошибке другого пакета.

Timeout запроса — 15 секунд. Для сетевой ошибки, HTTP 429 и 5xx разрешено до
двух повторов с задержкой. HTTP 400/401 не повторяются. Ответы и URL ошибок
провайдера не выводятся, чтобы исключить раскрытие ключа. Нет автоматического
перехода с ошибочного ответа Яндекса на геометрическую модель.

`rows[i].elements[j]` соответствует origin i → destination j:

- `duration.value` переводится из секунд в минуты без округления;
- `distance.value` сохраняется в метрах;
- `status=FAIL` сохраняется как недоступный переход;
- неверная форма ответа или некорректная OK-ячейка останавливает расчёт.

Недоступная дорога к заказу отклоняет маршрут с `UNREACHABLE`. Недоступный обратный
путь отображается как «—» и не запрещает доставку: возвращение не входит в SLA.

Результат содержит `matrixProvider=YANDEX_DISTANCE_MATRIX`, а `matrixStats`:
`requests`, `requestedElements` (включая попытки повторов), `cacheHits`,
`uniquePoints`, `modes`, `traffic`, `ttlSeconds`. UI показывает источник,
число HTTP-вызовов и запрошенных ячеек. Метрика Matrix сохраняет теоретический
размер (N+1)² на транспорт и не равна расходу API.

## Проверка

### Реальный пример расхода

На тестовом срезе 01.10.2026 13:35 диапазона 13:00–14:00: 18 заказов,
18 уникальных точек вместе с филиалом (есть совпадающие координаты).

| Расчёт | Ячейки | HTTP-запросы |
| --- | ---: | ---: |
| Полная матрица без кеша | 306 | Зависит от упаковки |
| Проверенный экономный запуск, K=5 | 117 | 16 |
| Повтор экономного запуска сразу | 0 | 0 |

В проверенном запуске расширений не потребовалось, выполнен один этап проверки.
Снижение количества ячеек относительно полной матрицы — около 62%. Это пример
расхода, а не гарантия экономии или совпадения бакетов: состав заказов, кеш,
пробки, транспорт и расширения меняют результат. Полная матрица здесь — расчёт
числа переходов, а не отдельное сравнение качества при тех же дорожных условиях.

`cacheHits` считает чтения по всем этапам и может повторно учитывать одну пару.
`requestedElements` считает отправленные ячейки, включая повторы; это расход
попыток API, не подтверждённый денежный счёт. Стоимость определяется тарифом и
оставшейся квотой. SQLite-кеш дорожных данных пока не реализован.

### HTTP-пример экономного запуска

```http
POST /api/v1/test-orders
Content-Type: application/json

{
  "at": "2026-10-01T13:35:00+05:00",
  "range": "13:00-14:00",
  "settings": { "matrixMode": "economy", "matrixNeighbors": 5 }
}
```

Для полной матрицы передайте `matrixMode: "full"`. Тестовый API изолирован от
рабочего сценария SQLite. Экономный режим через HTTP требует подключённый клиент
Яндекса; при локальном провайдере сервер возвращает `MATRIX_KEY_MISSING`.

### Тесты и CLI

```sh
rtk npm test
rtk npm run test:orders -- 2026-10-01T13:35:00+05:00 13:00-14:00
```

Автоматические тесты используют подставной HTTP-ответ и не расходуют квоту.
Вторая команда с ключом в `.env` обращается к реальному Яндексу.
